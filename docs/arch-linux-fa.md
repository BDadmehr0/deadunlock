# راهنمای نصب و اجرا روی Arch Linux

این نسخه آزمایشی برای **نسخهٔ ویندوزی Deadlock تحت Proton** و دسکتاپ **X11**
است، نه نسخهٔ بومی لینوکس یا Wayland. کارکرد با بازی و نسخهٔ فعلی offsetها
تأیید نشده است؛ استفاده ممکن است خلاف قوانین بازی باشد و به مسدود شدن حساب منجر شود.

## پیش‌نیازها

- یک سیستم Arch Linux به‌روز، دسترسی اینترنت، و Python نسخهٔ 3.11 یا جدیدتر.
- Steam و Deadlock با Proton، که باید جداگانه نصب و در Steam تنظیم شوند.
  نصب Steam روی Arch ممکن است به فعال‌سازی مخزن `multilib` نیاز داشته باشد.
- نشست X11 و افزونه‌های XTEST و XInput2؛ Xwayland در نشست Wayland برای ورودی سراسری
  پنجره‌های Wayland پشتیبانی نمی‌شود. مقدار `echo "$XDG_SESSION_TYPE"` را بررسی کنید.
- برای ESP، یک compositor فعال و بازی در حالت borderless/windowed روی مانیتور
  اصلی با اندازهٔ تمام صفحه. overlay جای پنجره را دنبال نمی‌کند و ممکن است در
  fullscreen انحصاری، روی چند مانیتور یا در بعضی window managerها درست کار نکند.

## نصب خودکار

داخل پوشهٔ پروژه، به‌عنوان کاربر معمولی (نه root) اجرا کنید:

```bash
./scripts/setup-linux.sh
```

اسکریپت برای نصب پیش‌نیازهای سیستمی `sudo pacman -Syu --needed` را اجرا می‌کند؛
این دستور **کل سیستم را به‌روزرسانی می‌کند** و از شما تأیید می‌خواهد. سپس محیط
`.venv` را می‌سازد یا مجدداً استفاده می‌کند و وابستگی‌های `requirements.txt` را
با pip نصب می‌کند. Steam و Proton را نصب نمی‌کند و تنظیمات امنیتی سیستم را تغییر
نمی‌دهد. در صورت نصب بودن همهٔ بسته‌های سیستمی می‌توانید مرحلهٔ pacman را رد کنید:

```bash
./scripts/setup-linux.sh --skip-system
```

برای دیدن گزینه‌ها `./scripts/setup-linux.sh --help` را اجرا کنید. اگر محیط
`.venv` ناقص یا به Python قدیمی وابسته است، پس از اطمینان از نداشتن اطلاعات
موردنیاز در آن، پوشه را پاک کنید و اسکریپت را دوباره اجرا کنید.

## نصب دستی

```bash
sudo pacman -Syu --needed python tk libglvnd libx11 libxi libxtst libxcb \
  libxkbcommon-x11 xcb-util-cursor xcb-util-image xcb-util-keysyms \
  xcb-util-renderutil xcb-util-wm xorg-xev
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
```

## اجرا

بازی را ابتدا در Steam با Proton اجرا کنید. سپس در پوشهٔ پروژه:

```bash
.venv/bin/python -m deadlock
```

در پنل، با زدن **Start** ایم‌بات و به‌صورت پیش‌فرض ESP شروع می‌شوند؛ برای
اجرای ایم‌بات بدون overlay، پیش از Start تیک **ESP overlay** را بردارید.
**Stop** یا بستن پنل، ESP مدیریت‌شده را هم متوقف می‌کند. برای aim دکمهٔ کناری
در تب Settings گزینهٔ **Aim button** را روی Mouse 4 یا Mouse 5 بگذارید و آن را
نگه دارید (معمولاً شمارهٔ ۸ یا ۹ در X11)؛ پیش‌فرض Mouse 4 است. کلیک چپ مستقل
شلیک می‌کند. قفل توانایی‌ها ممکن است بدون نگه‌داشتن دکمه هم aim را فعال نگه دارد.
در Settings مقدار **Target selection** را روی `distance` بگذارید تا نزدیک‌ترین
دشمن زنده در فضای سه‌بعدی هدف شود؛ دشمن پشت دیوار یا خارج صفحه هم ممکن است
انتخاب شود. تنظیم ذخیره‌شدهٔ قبلی حفظ می‌شود؛ پس اگر `fov` است آن را تغییر دهید
و Stop/Start بزنید. هدف‌گیری به‌طور پیش‌فرض به استخوان شناسایی‌شده نیاز دارد؛
اگر خواندن اسکلت موفق نشود برای آن هدف aim متوقف می‌شود. فقط با فعال‌کردن
**Allow estimated aim when skeleton is unavailable** در Aim Zones، ارتفاع
تخمینی به‌جای اسکلت به کار می‌رود. offsetهای اسکلت هنوز روی بازی واقعی تأیید
نشده‌اند.
این دکمه به XInput2 نیاز دارد و در Wayland/Xwayland ممکن است وضعیت سراسری آن
دریافت نشود. با ابزار `xev` می‌توانید شمارهٔ دکمهٔ خود را بررسی کنید.
پیام‌ها و خطاهای ESP
در تب **Logs** و وضعیت پردازش آن در نوار پایین دیده می‌شوند. اگر ESP متوقف
شود، ایم‌بات تا زدن Stop به کار ادامه می‌دهد. ESP با یک پردازش جدا و دسترسی
فقط‌خواندنی به حافظه اجرا می‌شود.

با فعال‌کردن **Live Save** در بالای پنل، تغییرات معتبر به‌صورت خودکار در
`deadlock/aimbot_settings.json` ذخیره و در اجرای بعدی بازخوانی می‌شوند. مقادیر
ناقص یا نامعتبر ذخیره نمی‌شوند و وضعیت خطا در تب Settings نمایش داده می‌شود.
با خاموش‌بودن Live Save نیز هنگام Start یا بستن پنل تنظیمات معتبر ذخیره می‌شوند.
ذخیره باعث تغییر تنظیمات ایم‌بات در حال اجرا نمی‌شود؛ برای اعمال آنها Stop و
سپس Start بزنید.

اجرای جداگانه نیز همچنان ممکن است:

```bash
.venv/bin/python -m deadlock.aimbot_gui  # پنل ایم‌بات بدون ESP
.venv/bin/python -m deadlock.aimbot      # خط فرمان
.venv/bin/python -m deadlock.esp         # فقط overlay
```

نام پیش‌فرض پردازش `deadlock.exe` است. در صورت متفاوت بودن نام، با متغیر
`DEADUNLOCK_PROCESS` نام دقیق را تعیین کنید. اگر PID پردازش بازی را می‌دانید،
می‌توانید به جای آن `DEADUNLOCK_PID` را تنظیم کنید؛ مقدار زیر فقط نمونه است:

```bash
DEADUNLOCK_PID=12345 .venv/bin/python -m deadlock
```

PID واقعی را مثلاً با `ps -u "$USER" -o pid,comm,args | grep -iE 'deadlock|project8'`
پیدا کنید؛ پردازش بازی را انتخاب کنید، نه `reaper`، Steam یا خود `grep`. در صورت
دسترسی، با `grep -i 'client\.dll' /proc/PID/maps` بررسی کنید که هدر فایل
`client.dll` در پردازش انتخاب‌شده mapping شده است (به جای `PID` شماره را بگذارید).
نسخهٔ فعلی به signature استفاده‌نشدهٔ `schemasystem.dll` نیازی ندارد.
ممکن است برای دیدن maps هم ابتدا تنظیمات دسترسی بخش بعد لازم باشد. اگر PID به
اشتباه انتخاب شود، از `DEADUNLOCK_PID` برای تعیین دستی آن استفاده کنید. در بعضی
چیدمان‌های Proton این فایل یا signatureها پیدا نمی‌شوند؛ همچنین به‌روزرسانی
بازی می‌تواند offsetها را تغییر دهد. اسکنر علاوه بر نگاشت فایل، نواحی ناشناس
داخل محدودهٔ تصویر PE را نیز بررسی می‌کند، اما درستی signatureها و سازگاری با
همهٔ چیدمان‌های Proton تضمین نشده است. نوشتن در آدرس اشتباه ممکن است بازی را خراب کند.

## دسترسی و عیب‌یابی

اگر ESP خطای `Qt xcb platform` می‌دهد، نشست و متغیرهای Qt را بررسی کنید:

```bash
printf 'session=%s DISPLAY=%s QT_QPA_PLATFORM=%s\n' "$XDG_SESSION_TYPE" "$DISPLAY" "$QT_QPA_PLATFORM"
QT_QPA_PLATFORM=xcb .venv/bin/python -m deadlock
```

بهتر است وارد نشست X11 شوید. روی Wayland، استفاده از xcb فقط از طریق Xwayland
آزمایشی است و شفافیت، ترتیب پنجره و ورودی سراسری ممکن است کار نکند. یک compositor
و کتابخانه‌های Qt/X11 نیز لازم‌اند.

اگر aim روشن می‌شود ولی هدفی پیدا نمی‌کند، پس از دریافت نسخهٔ جدید و هنگام حضور
در مسابقه، گزارش **فقط‌خواندنی** زیر را اجرا کنید و `12345` را با PID واقعی بازی
جایگزین کنید:

```bash
.venv/bin/python -m deadlock.diagnostics --pid 12345
```

این گزارش به‌طور پیش‌فرض ۱۵ slot را مثل aimbot بررسی می‌کند و نشان می‌دهد خواندن
کدام slotها شکست خورده یا به‌خاطر تیم و جان رد شده‌اند؛ در حافظه نمی‌نویسد و
ورودی نمی‌فرستد. برای بررسی slotهای بیشتر از `--slots 256` استفاده کنید (حداکثر
۲۰۴۸). بازیکنان پیدا‌شده خارج از ۱۵ slot اول جداگانه علامت می‌خورند؛ این گزینه
محدودهٔ جست‌وجوی خود aimbot را تغییر نمی‌دهد. برای دیدن تمام خطاها می‌توانید
`--show-unreadable` اضافه کنید. حذف `--pid` از تشخیص خودکار یا `DEADUNLOCK_PID`
استفاده می‌کند. دسترسی خواندن پردازش همچنان مشمول ptrace/Yama است. وجود candidate
به‌معنی معتبر بودن دوربین، استخوان‌ها یا offsetهای نوشتن نیست.

اگر شناسهٔ قهرمان `0` یا ناشناخته باشد، برنامه هدف‌گیری را متوقف می‌کند و منتظر
دادهٔ معتبر می‌ماند؛ این مقدار را نباید به‌عنوان قهرمان واقعی فرض کرد. وارد یک
مسابقه با قهرمان انتخاب‌شده شوید. اگر هشدار ادامه داشت، PID بازی، نسخهٔ بازی،
signatureها و offsetهای ثابت را بررسی کنید. معتبر بودن یک شناسه به‌تنهایی ثابت
نمی‌کند آدرس‌های حافظه برای نوشتن درست هستند.

اگر دسترسی به `/proc/<pid>/mem` رد شد، بازی و برنامه را با یک کاربر معمولی اجرا
کنید و تنظیمات ptrace/LSM و dumpable بودن پردازش را بررسی کنید. بازی یا GUI را
با root اجرا نکنید. در سیستم‌هایی که Yama فعال است، مقدار آن را بررسی کنید:

```bash
cat /proc/sys/kernel/yama/ptrace_scope
```

اگر سیاست امنیتی سیستم اجازه می‌دهد، مدیر سیستم می‌تواند موقتاً مقدار را به صفر
تغییر دهد و **پس از پایان کار مقدار قبلی را بازگرداند**. مثال زیر باید در همان
ترمینال اجرا شود تا مقدار قبلی حفظ شود:

```bash
old_scope=$(cat /proc/sys/kernel/yama/ptrace_scope)
sudo sysctl -w kernel.yama.ptrace_scope=0
# برنامه را در همین فاصله اجرا و آزمایش کنید؛ پس از پایان کار:
sudo sysctl -w "kernel.yama.ptrace_scope=$old_scope"
```

این تغییر محدود به برنامه نیست و حفاظت **کل سیستم** را کاهش می‌دهد. در بعضی
پیکربندی‌ها (برای مثال مقدار 3) کاهش آن بدون راه‌اندازی مجدد ممکن نیست و سایر
محدودیت‌ها همچنان می‌توانند دسترسی را مسدود کنند. اسکریپت این تغییر را انجام نمی‌دهد.

اگر Qt افزونهٔ `xcb` را بارگذاری نمی‌کند، وجود کتابخانه‌های X11 و نشست X11 را
بررسی کنید؛ بعضی محیط‌ها به بسته‌های سیستمی اضافی نیاز دارند. ورودی مصنوعی XTEST
ممکن است توسط بعضی بازی‌ها یا تنظیمات Proton پذیرفته نشود.
